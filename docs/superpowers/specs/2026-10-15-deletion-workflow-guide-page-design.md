# 삭제 워크플로우 로직 가이드 페이지 — 설계

## 목적
회사 운영 담당자·팀원이 삭제 워크플로우의 프로세스 로직(어떤 순서로 무엇을 판단해 어떤 정책이 삭제/공지 대상이 되는가)을 앱 안에서 이해할 수 있게 하는 읽기 전용 설명 페이지.

- 대상 독자: 코드를 모르는 운영 담당자. 개발 상세(클래스명, 설정 키)는 제외.
- 범위: 삭제 워크플로우만. 동기화·분석 엔진 등 다른 기능은 제외.

## 결정 사항
- 시각화: React + Tailwind 직접 구현 (신규 의존성 없음, 앱 테마/다크모드 일치).
- 위치: 프론트 전용 라우트 `/guide/deletion-workflow` (백엔드 수정 불필요 — SPA catch-all). Navbar에 "Guide" 링크 추가.
- 내용 정본: **코드**(`core/pipeline.py` docstring + 각 processor). 운영 매뉴얼은 참고만.

## 페이지 구성
1. **한눈에 보기** — 목적, 삭제 대상 유형, 최종 공지 파일.
2. **전체 흐름도** — Phase 0~6 세로 플로우. 각 단계에 입력/산출물 요약. 클릭 시 상세 카드로 스크롤.
3. **정책 한 건의 운명** — 의사결정 트리: 예외 → 중복 → 만료 여부 → 사용 여부 → 분류 결과(기간만료/만료미사용/장기미사용/이력없음미사용/제외).
4. **Phase별 상세 카드** — 접이식. 목적, 판단 기준, 실무적 의미(예: 하단 최신정책, 차단영향위험).
5. **용어·기준표** — `예외` 값 우선순위, 사용/미사용 기준일, 신청유형(P/F/S/M), 자동연장 체인 판별.
6. **자주 겪는 문제** — 매뉴얼 13절 요약 (코드 대조 후).
7. 하단에 기준 출처(`pipeline.py`)와 최종 확인일 표기.

## 파일 구조 (파일당 코드 1000줄 이하)
`frontend/src/pages/guide/` 하위에 페이지 + 섹션별 컴포넌트 + 콘텐츠 데이터 파일로 분리. 흐름도/의사결정 트리용 소형 컴포넌트는 공용 재사용 단위로 분리. 상세 구조는 구현 계획에서 확정.

## 정확성 검증 (필수 단계)
코드 대조 중 이미 확인된 매뉴얼-코드 불일치:
- 장기미사용 공지 대상: 코드는 **GENERAL만**(예외 NaN 또는 자동연장정책). 매뉴얼은 GROUP 포함으로 기재.
- 코드에는 `공지대상` 컬럼(유지정책/중복정책 삭제대상/기간만료/만료미사용/장기미사용/이력없음미사용)이 있으나 매뉴얼에 없음. 출력 파일명도 상이.
- 기준일(최근 N일 신규정책, 미사용 N일)은 설정값(기본 90일).

각 Phase 콘텐츠는 작성 시 해당 processor 코드와 대조하고, 불일치는 코드 기준으로 쓰며 사용자에게 보고한다. 매뉴얼 자체 수정은 이번 범위 밖(별도 요청 시).

## 테스트
- `npm run lint` / `npm run build`(tsc) 통과.
- 개발 서버에서 페이지 렌더, 라우트 접근, 내비 링크, 클릭 스크롤, 다크모드 확인.

## 비범위
매뉴얼 문서 수정, 다국어, 실데이터 연동, 개발자용 기술 상세.
